OpenAI claims language-model agents that write a threat model of an application and check a function, or a code commit, against it

2026-11-16Filings

Listen · Thinking Makes It So, 2026-11-16 · 9 min

All episodes · Subscribe: Apple Podcasts · Spotify

United States Patent Application Publication Nos. 2026/0350180 A1, "Detecting Vulnerabilities in Computer Functions Utilizing Generative Model Agents," Application No. 19/365,022, and 2026/0350179 A1, "Detecting Vulnerabilities in Code Commits Utilizing Generative Model Agents," Application No. 19/364,425, OpenAI OpCo, LLC, both filed October 21, 2025, both claiming priority to United States Provisional Patent Application No. 63/798,122, filed May 1, 2025, both published November 5, 2026

The two applications share three inventors and one provisional application, and they divide the same idea by the unit of code examined. In Publication No. 2026/0350180, claim 1 retrieves a function from the application's function repository, ranks its vulnerability using a call graph of how the application's functions relate, has a large language model generate a threat model as a structured data object, and has a large language model analyze the function together with the threat model to produce a threat object. Claim 1 of Publication No. 2026/0350179 is shorter: it retrieves a commit, has a large language model generate a threat model, and has a generative threat analysis agent analyze the commit with the threat model, with no ranking or call graph; its claim 5 adds a directed graph of the modified functions' calls, annotated with taint attributes through schema-constrained prompts, and a threat risk score for the commit. Claim 6 of each application builds a runtime threat environment holding a cloned version of the function or commit and generates a validated threat object confirming the threat from the clone's execution; in the function application, the large language model does this inside that environment. The USPTO's Open Data Portal shows both applications awaiting first examination.

What it changesMy reading is that OpenAI is staking ground in security agents that review code, and that the claims it keeps will be the dependent ones. Claim 1 of each application recites the steps of a security review carried out with a language model, and the commit application's own background says that some existing systems already use large language models to scan code for common patterns or known bugs. I expect both applications to settle on their mechanisms: the taint annotation and risk score of claim 5 in the commit application, and the confirmation inside a cloned runtime environment that claim 6 of each application recites. If you are drafting claims for an agent that finds defects in code, consider writing at least one independent claim that includes confirming the finding by running the code in an isolated environment, rather than holding that step, as OpenAI did, only in dependent claims.
